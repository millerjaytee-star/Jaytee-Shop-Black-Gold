# Controlled Pilot Operating Model

Initial real-customer work runs in **SHADOW MODE**.

1. Customer onboarding and authorized data collection.
2. Ingestion, mapping, validation, normalization and reconciliation.
3. Deterministic metrics, scores, forecast outputs and canonical opportunities.
4. Analyst review of data conflicts, confidence, financial materiality and recommendations.
5. Operator validates operational context.
6. Approved intelligence is released.
7. Opportunities create owned actions.
8. Stabilis records observed outcomes.
9. Verification review determines whether any financial impact qualifies as Verified Value.
10. Calibration events capture engine prediction, analyst agreement, operator agreement, implementation and eventual result.

Pilot success is evaluated separately from customer financial performance using onboarding completion, time-to-first-diagnostic, opportunity acceptance, action creation/completion, analyst review time, login/return frequency, report usage and verified-value conversion.

## First-month research plan

| Week | Target | Record as an actual result |
|---|---|---|
| 1 | Interview ten operators about a recent labor miss. | Interview date, the records available, how the operator answered the question, effort, missing evidence and whether anyone owned a follow-up. |
| 2 | Seek three paying operators for scoped one-location pilots. | Inquiry, signed proposal, cleared payment and kickoff as distinct dated events. Count a paid pilot after cleared payment. |
| 3 | Automate the parts that repeat across usable exports. | The repeated mapping or reconciliation step, number of occurrences, analyst minutes, exceptions and evidence quality before and after. |
| 4 | Measure repeat use. | Whether the owner returned for a comparable week, accepted and completed actions by their due dates, and requests for another cycle. |

For one real review, observe the buyer using its existing configured workflow, such as Restaurant365 or Homebase. Use the same location, week, sources and decision for the Stabilis review. Time from usable exports to the first correct, explained variance. Record analyst and support minutes separately, manager effort, which evidence changed the decision and where either workflow reached the same answer. If the configured incumbent reaches an equivalent result, record it and assess implementation support as a service. Keep industry expansion, larger groups, native apps and subscriptions for later decisions.

## Private founder log template

Use the approved restricted folder. Keep the log separate from the customer workspace and public site. Store source files under the signed scope and raw-file retention terms, and use permitted references in the log. The columns below are a template. This build contains no real pilot measurements or commercial events.

| Log | Fields |
|---|---|
| Commercial events | Pilot ID, event type (inquiry, signed proposal, cleared payment, kickoff), date and time, evidence reference, founder notes. Record the agreed one-location scope and confirm minimum data readiness before kickoff. |
| Review timing | Pilot ID, location reference, fiscal week, first usable export time, first explained variance time, elapsed minutes, analyst minutes, support minutes, incumbent method, incumbent elapsed and manager minutes, Stabilis manager minutes, decision and evidence that changed it. |
| Follow-through | Pilot ID, review and action IDs, assignee, assigned time, due time, accepted time, completion time, evidence reference, next review, owner return time, another cycle requested and request time. |
| Research outcomes | Date, week, target, actual count or value, source reference and decision. Leave an unmeasured result blank. Record a zero only where measurement established a count of zero. |
